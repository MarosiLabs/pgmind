# eval/ — benchmarks, corpora, published results

The evaluation harness enforces the phase gates defined in [PRODUCT-PLAN.md Part III](../docs/PRODUCT-PLAN.md). Run with `make eval` from the repo root; the report lands in `eval/results/latest.json` (gitignored — published numbers are committed deliberately alongside phase exits).

- `harness.py` — suite runner. Suites report `ok` / `fail` / `pending`. Phase 1 suites delegate to the pure-Rust `pgmind-eval` binary; Phase 2 suites (RFC-003 §5 / RFC-004 §5) install the extension into a throwaway unix-socket cluster (pg_config from `PGMIND_PG_CONFIG` or the pgrx-managed install) and exercise real storage: `identity-semantics` / `extraction-correctness` / `tenant-isolation` run the pg_test goldens, `storage-round-trip` pushes the repo corpus + 10k seeded fuzz documents through `write()`/`read()`/`verify_note`, `capacity-model` measures sizes and p95 latencies at 10k notes and, in a throwaway database of its own, the **write cost**: five 1,000-note create passes for a median and a spread, plus an ablation (same notes without links/tags, and one-block notes) so RFC-003 D8 can attribute the per-note cost instead of inferring it — published to `published/capacity-model-v1.json` honestly, including the throughput number when it misses the design target, `dump-restore` proves `pg_dump` → plain autocommit `psql` restore of a vault that CARRIES HISTORY, with the table set enumerated from `pg_catalog` (a literal list is how a missing registration goes unnoticed). Phase 3 (RFC-005 §5) adds `history-fidelity` (every revision reconstructs to the bytes that were written), `concurrency` (CAS contract + 8 concurrent appends, rendezvousing on `pg_blocking_pids` rather than sleeping), and `gate-selftest` — a negative control that breaks each checker's subject and asserts the checker notices.
- `rebinding.py` / `rebinding_tuning.py` — the adversarial edit corpus's parser, scorer and reindexer, and the RFC-004 Part B threshold study. `make reindex-corpus` stamps each case with the blocks the parser actually produced; the gate fails on a stale stamp.
- `corpora/` — fetched or curated test corpora (gitignored when downloadable). `corpora/pgmind/rebinding/` is the **adversarial edit corpus**: committed, hand-authored, and a deliverable in its own right (see its README for the format and the ground-truth semantics).
- `results/` — machine-readable reports (gitignored).
- `published/` — committed gate results at phase exits (`phase-1-gates.json`: all five RFC-002 suites ok; `phase-2-gates.json`: all six RFC-003 §5 / RFC-004 §5 suites ok, with `capacity-model-v1.json` as the capacity deliverable it points at; `rebinding-baseline-v1.json` and `rebinding-tuning-v1.json` for RFC-004 §5 Part B).

Phase 3 also adds `excision-completeness` (erasure reaches every column the catalog knows about, and the checker is proven able to find what redaction leaves behind) and `rebinding-edit-corpus` (RFC-004 §5 Part B). That last one gates on the corpus being *well-formed*, not on a score: the published match-rate is itself the deliverable, and a threshold nobody has earned the right to set yet would be an acceptance the owner has not given. It does fail on three things — an unparseable corpus, a stale case index, and a regression in the deterministic control category.

Rules: gates are defined at RFC acceptance (no gate, no acceptance); numbers get published even when unflattering — the rebinding match-rate especially. As of the first measurement the engine carries **0 of 22** bindings that require inference, which is exactly what RFC-004 A3 says it does and is the number Part B exists to move.
