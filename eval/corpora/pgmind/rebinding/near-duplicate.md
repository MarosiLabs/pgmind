# near-duplicate

Documents that repeat themselves. Exact content match pairs equal-hash blocks *k*-th ↔ *k*-th in document order (RFC-004 A3 pass 2), which is the only stable rule available — and is provably wrong whenever the edited occurrence is not the last one. These cases pin how wrong.

## case: dup-edit-first-of-two

**why:** two byte-identical paragraphs; the **first** is edited. The survivor's hash now matches two old blocks, and k-th ↔ k-th pairs it with the wrong one — a mis-binding the engine reports as a successful carry.

### before

`````markdown
# Doc

The same sentence, written twice on purpose.

The same sentence, written twice on purpose.
`````

### after

`````markdown
# Doc

The same sentence, written twice on purpose, then edited.

The same sentence, written twice on purpose.
`````

- before[0] => after[0]
- before[1] => after[1]
- before[2] => after[2]

## case: dup-remove-middle

**why:** three identical items, the middle one removed.
**ambiguous:** the items are byte-identical, so *which* one was removed is unobservable; the convention (k-th ↔ k-th) makes it the last, and the ground truth follows the convention rather than the author's intent. Each item is two blocks (`list_item` plus its paragraph), so the convention has to hold at both levels or the survivor's item and its text disagree about who they are.

## case: dup-boilerplate-section-removed

**why:** the same one-line boilerplate under three headings, and the middle section is deleted. The hashes cannot tell the three apart; the headings can. This case was authored expecting k-th ↔ k-th to bind the survivor to section B's line — the engine binds it to C's, because A3 pass 2 is **section-first**: equal-hash candidates are paired within a `heading_path` before they are paired by document order. The corpus was wrong and the accepted rule was right, which is what a corpus is for. It also settles half of a Part B open question in advance: locality is already a signal on the deterministic path, so a heuristic stage that ignores `heading_path` would be *less* discriminating than the pass above it.

`````markdown
## A

See also.

## B

See also.

## C

See also.
`````

### after

`````markdown
## A

See also.

## C

See also.
`````

## case: dup-kind-change

**why:** the same text, reclassified. Kind is inside the content hash (RFC-002 D7), so a paragraph and a list item of the same words are different blocks by construction — but a list item *contains* a paragraph in this model, and that inner paragraph has the same kind and the same words. So the question this case actually asks is which of the two readings the storage model commits to: the text survived inside a new wrapper, or the block became something else. The ground truth takes the model at its word — the paragraph continues, the `list_item` is new.

### before

`````markdown
Alpha beta gamma delta.
`````

### after

`````markdown
- Alpha beta gamma delta.
`````

### same

- before[0] => after[1]   # the paragraph inside the new item
