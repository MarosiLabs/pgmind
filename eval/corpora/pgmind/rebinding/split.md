# split

One block becomes several. RFC-004 A2's convention is **first fragment keeps the ID**; these cases probe where that convention is obviously right, where it is merely a coin-toss, and where a containment heuristic would call something a split that isn't one.

## case: split-sentence

**why:** a paragraph split at a sentence boundary — the canonical shape.

### before

`````markdown
# Ledger

The engine records pre-images anchored at the current state. Reconstruction never invokes the parser.
`````

### after

`````markdown
# Ledger

The engine records pre-images anchored at the current state.

Reconstruction never invokes the parser.
`````

### same

- before[0] => after[0]   # heading, untouched
- before[1] => after[1]   # first fragment keeps

## case: split-three-fragments

**why:** three fragments, and the bulk of the text lands in the middle one.
**tension:** first-keeps hands the ID to the shortest fragment; a reader asked "which one is the original paragraph?" would point at the middle.

### before

`````markdown
# Retention

Old revisions cost storage. The retention policy trims them on a schedule the operator sets and the audit log records. Excision is a separate and much louder thing.
`````

### after

`````markdown
# Retention

Old revisions cost storage.

The retention policy trims them on a schedule the operator sets and the audit log records.

Excision is a separate and much louder thing.
`````

### same

- before[0] => after[0]
- before[1] => after[1]

## case: split-decoy-lead-in

**why:** looks exactly like a split to a containment heuristic — one old block, two new neighbours that between them contain it — but it is an insert plus an edit-in-place, and first-keeps would put the identity on text the author had never written before.

### before

`````markdown
Alignment must be order-monotonic. Crossing matches are how a rebinder invents a move nobody made.
`````

### after

`````markdown
Two rules govern alignment.

Alignment must be order-monotonic. Crossing matches are how a rebinder invents a move nobody wrote.
`````

## case: split-list-item

**why:** a split inside a list, where every following item's ord shifts too. A list item is two blocks in this model — the `list_item` and the paragraph inside it — so one visible split is two, and the ground truth has to hold for both.

### before

`````markdown
- alpha and its consequences
- beta and its consequences
- gamma and its consequences
`````

### after

`````markdown
- alpha and its consequences
- beta
- and its consequences
- gamma and its consequences
`````

### same

- before[0] => after[0]   # item alpha
- before[1] => after[1]   # its paragraph
- before[2] => after[2]   # item beta, first fragment keeps
- before[3] => after[3]
- before[4] => after[6]   # item gamma, shifted by two ords
- before[5] => after[7]

## case: split-code-block

**why:** same-kind split where the fragments are not natural language — token bigrams over SQL keywords are far more self-similar than prose, so any threshold tuned on paragraphs is being asked a different question here.

### before

`````markdown
```sql
SELECT knowledge.write('a', $$x$$::markdown);
SELECT knowledge.read('a');
SELECT knowledge.history('a');
SELECT knowledge.blame('a');
```
`````

### after

`````markdown
```sql
SELECT knowledge.write('a', $$x$$::markdown);
SELECT knowledge.read('a');
```

Then the history side:

```sql
SELECT knowledge.history('a');
SELECT knowledge.blame('a');
```
`````

## case: split-marked-fragment

**why:** the author pinned identity on the *second* fragment with an `^id` marker. A user assertion carried in the text beats the first-keeps convention, and it does so deterministically — no threshold involved.

### before

`````markdown
# Notes

The pre-image script is KEEP and INS and nothing else. ^script
`````

### after

`````markdown
# Notes

The pre-image script is KEEP and INS.

And nothing else. ^script
`````

### same

- before[0] => after[0]
- before[1] => after[2]
