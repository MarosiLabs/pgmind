# merge

Several blocks become one. RFC-004 A2's convention is **the dominant source keeps the ID**. These cases put dominance in each position in turn — first, last, nowhere — so a rule that quietly means "the first one" is visible as such.

## case: merge-two-paragraphs

**why:** the plain shape: two paragraphs joined, the longer one first, convention and intuition agreeing.

### before

`````markdown
The ledger anchors pre-images at the current state, which is what makes reconstruction cheap.

It never invokes the parser.
`````

### after

`````markdown
The ledger anchors pre-images at the current state, which is what makes reconstruction cheap. It never invokes the parser.
`````

## case: merge-equal-halves

**why:** neither source dominates.

Identity is minted on write and never inferred.

Position is recomputed on every write, always.

## case: merge-three-last-dominant

**why:** three sources into one, and the dominant source is the **last** — a rule that means "first" gets this wrong while still reporting a carry.

### before

`````markdown
The tile lane stores bytes.

The block lane stores meaning.

Neither lane is ever derived from the other at read time, which is what keeps a read from needing the parser at all.
`````

### after

`````markdown
The tile lane stores bytes. The block lane stores meaning. Neither lane is ever derived from the other at read time, which is what keeps a read from needing the parser at all.
`````

## case: merge-across-heading

**why:** the merge crosses a section boundary and dissolves the second heading, so the surviving block changes `heading_path` as well as content.

### before

`````markdown
## Writes

Every write takes the note row lock before it reads anything that decides the outcome.

## Reads

Reads take no lock at all.
`````

### after

`````markdown
## Writes

Every write takes the note row lock before it reads anything that decides the outcome. Reads take no lock at all.
`````

- before[0] => after[0]
- before[1] => after[1]
