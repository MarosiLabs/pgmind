# The adversarial edit corpus

Ground truth for **block identity across a whole-document rewrite**: the edit shapes that arrive when a document is replaced from outside the block ops — sync, re-import, an agent that rewrites a file instead of editing a block. RFC-004 Part A handles these deterministically (`^id` claims, then exact content match); Part B proposes a heuristic stage between them and minting. This corpus is Part B's gate, and it is a **deliverable in its own right** (plan §16): the published match-rate *is* the result, favourable or not.

It is committed, hand-authored and meant to grow. When someone finds an edit that loses identity in a way that surprises them, the fix is a case here first.

## Format

One file per category, several cases per file. A case is:

````markdown
## case: some-name

**why:** one line — what this shape attacks.
**tension:** (optional) where the RFC's convention and a reader's intuition part ways.
**ambiguous:** (optional) why the ground truth here is a convention, not an observable fact.

### before

`````markdown
the document as first written
`````

### after

`````markdown
the document as replaced
`````

### same

- before[1] => after[2]   # free-text note

### index

<!-- generated by `make reindex-corpus` — do not hand-edit -->
````

Fences are **five** backticks (case content contains three). The `### index` section is generated: it lists the blocks the parser actually produced for `before` and `after`, in document order, so ground truth is written against observed ords instead of guessed ones. `make reindex-corpus` regenerates it; the gate suite regenerates it too and **fails if it drifts**, because a stale index means the ground truth below it is being read against a document that no longer parses that way.

## What `### same` means

Each pair asserts: *this `after` block **is** that `before` block, continued* — a reader who cares about the history, citations and embeddings attached to it would say the identity survived. Consequences of the pairs, all checked:

- an `after` ord in no pair **must be minted** — carrying an ID onto it is a false positive;
- a `before` ord in no pair **must be released** — its ID must not appear after the write;
- identity is 1:1 — the parser here rejects a corpus that binds either side twice.

`- (nothing carries)` is how a case asserts that *no* identity should survive. Those cases are the precision half of the corpus, and they are the reason a positional aligner cannot quietly score well here.

Where the shape is genuinely ambiguous — an edit no algorithm could resolve, like which of two byte-identical paragraphs was deleted — ground truth encodes **the RFC's declared convention** (split: first fragment keeps; merge: dominant source keeps; duplicates: k-th ↔ k-th in document order) and the case carries an `**ambiguous:**` line saying so. Encoding intuition instead would gate the engine against semantics the project deliberately rejected.

## Scoring

Two-sided, per category and overall:

- **recall** = bindings the ground truth expects that the engine made — identity *dropped* is churn: new IDs, broken citations, re-embedding.
- **precision** = bindings the engine made that ground truth accepts — identity *misplaced* is worse than churn, because history, citations and embeddings silently follow the ID onto content that is not theirs, and nothing downstream can tell.

A wrong carry onto a block whose `before` counterpart *is* in the ground truth is reported separately as **misbound**: the engine had the right block in hand and put it in the wrong place.
