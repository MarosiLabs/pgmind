# edit-in-place

The headline case, and the one RFC-004 A3 documents as churning identity today: a block is edited and the document is rewritten whole. Position is unchanged, content is not. Every case here is a binding a reader would call obvious.

## case: typo-fix

**why:** one character. The cheapest possible edit, and the one users notice losing identity over.

### before

`````markdown
# Notes

The reconstruction path never invokes the parsr, which is the whole point of the two lanes.
`````

### after

`````markdown
# Notes

The reconstruction path never invokes the parser, which is the whole point of the two lanes.
`````

- before[1] => after[1]

## case: heading-word-added

**why:** a heading gains two words. Every descendant's `heading_path` changes with it, so a rebinder that folds `heading_path` into its similarity signal has to not double-count the same edit.

### before

`````markdown
## Concurrency

The lock order is note row, then path name, then nothing else.
`````

### after

`````markdown
## Concurrency and locking

The lock order is note row, then path name, then nothing else.
`````

- before[1] => after[1]

## case: checkbox-toggle

**why:** a task is ticked. The document's bytes change, so nothing short-circuits — but the checkbox state lives in `attrs`, not in the block's content, so the content hash does not move and identity survives without any heuristic at all. Recorded because it looks like the hardest edit shape there is and is in fact free.

### before

`````markdown
- [ ] write the corpus
- [ ] publish the number
`````

### after

`````markdown
- [x] write the corpus
- [ ] publish the number
`````

## case: code-one-line-changed

**why:** one line of four inside a fenced block. Code is far more self-similar than prose, so the same threshold means something different here.

## case: sentence-deleted

**why:** a long paragraph loses one sentence of four. Similarity is high, length changed by a quarter — a shape a containment metric can mistake for a merge remnant.

### before

`````markdown
Writes take the row lock first. Reads take no lock at all. The path name has a lock domain of its own, which is what keeps two creations of the same path from both succeeding. Everything else is compare-and-set.
`````

### after

`````markdown
Writes take the row lock first. Reads take no lock at all. Everything else is compare-and-set.
`````

## case: tiny-block-one-word

**why:** two-word blocks, one word changed. Token bigrams have almost no signal at this length, so a τ that passes the long-paragraph cases will either miss this or start accepting noise — the case that makes the threshold choice a trade-off rather than a free parameter.

### before

`````markdown
Locks first.

Reads later.
`````

### after

`````markdown
Locks always.

Reads later.
`````
