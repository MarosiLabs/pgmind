Manual

The pgmind manual

pgmind keeps a markdown vault — notes, sections, paragraphs, links, tags — as PostgreSQL rows, so many agents can write to it at once and every paragraph has an address you can cite.

Research pre-alpha. Everything here runs today, but the SQL surface is unstable and there is no upgrade path between builds. Anything not built yet is marked Phase 5 and never shown as working SQL.

What it looks like

The whole API in one screen. Markdown goes in, the same bytes come out, and everything in between is a row.

psql
CREATE EXTENSION pgmind;

-- A note is markdown at a path.
SELECT knowledge.write('projects/auth', $md$# Auth

## Decisions

- [[oauth2]] over server sessions, see [[rfc/auth-01]] #architecture
- Refresh tokens rotate every 24h #decision ^rotation
$md$);

SELECT knowledge.read('projects/auth');            -- byte for byte
SELECT * FROM knowledge.blocks('projects/auth');   -- every piece, as rows
SELECT * FROM knowledge.backlinks('projects/auth');-- what points here

-- Add a line under a heading. Two agents doing this at once both succeed.
SELECT * FROM knowledge.append_to_section(
    'projects/auth', ARRAY['Auth','Decisions'],
    $md$- Access tokens live 15 minutes #decision$md$);

-- Nothing was overwritten.
SELECT seq, verb, author FROM knowledge.history('projects/auth');
SELECT knowledge.read_as_of('projects/auth', 0::bigint);

How to read this

Every SQL example was run against PostgreSQL 18 and its output pasted back. UUIDs are shortened to 019fd618-… because yours will differ. Badges say what is real:

BadgeMeans
In main Runs today.
Phase 5 Designed, not built. Shown so you can plan around it.
Cut / Unscheduled Withdrawn, or not on any phase. Shown because another document names it and you would otherwise go looking.
Admin / Internal Lives in the pgmind schema, below the public API. Several are destructive; some are documented only so you recognise them in a stack trace.
PM0xx An error code the call can raise.
One habit worth forming before your first write

The six block operations return SETOF pgmind.op_result — one row, (revision, block_ids). Call them from FROM: SELECT * FROM knowledge.update_block(…). The select-list form is safe too, because a set-returning expression is evaluated once; while these returned a scalar composite it applied the edit twice, which is why every example on this site uses FROM.

Going deeper

This manual describes the code. Behind it sit the design documents, in order of precedence: the handbook (the architecture laws), the accepted RFCs (one per phase), the product plan, and then the code. Measurements are published in eval/, including the unflattering ones.

Where this manual disagrees with the code, the manual is wrong — please say so.
